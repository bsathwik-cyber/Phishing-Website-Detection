# Security policy

## Intended use

PhishGuard is an educational, local URL-classification prototype. Use it only for URLs and datasets you are authorised to analyse.

The current application analyses URL strings and does not fetch the destination website. A classification is a screening signal, not a guarantee that a destination is safe or malicious.

## Deployment boundary

- The Flask development service binds to `127.0.0.1` and is configured for the local Next.js development origin.
- The application does not currently provide authentication, tenant isolation, or production deployment hardening.
- Do not expose the development API directly to the public internet.
- Uploaded batch files are limited to 1 MiB and the application processes at most 500 rows from a batch.

## Local data

Scan history is stored in `backend/phishguard.db`. Submitted URLs may contain sensitive identifiers, query parameters, internal hostnames, or access tokens. Keep the database, bulk inputs, exported results, and backups private. They are excluded from Git by default.

Never commit API tokens, passwords, private URL lists, production scan histories, or unredacted logs.

## Model artifacts

The model is serialized with Python pickle. Loading an untrusted pickle file can execute arbitrary code. Only load model artifacts generated by your own trusted local training run or from another source you have independently verified.

## Reporting a vulnerability

For a security issue in this repository, do not publish sensitive data or working exploit details in a public issue. Contact the repository owner privately through GitHub's profile contact options and provide a concise description, affected file/endpoint, impact, and safe reproduction steps.
